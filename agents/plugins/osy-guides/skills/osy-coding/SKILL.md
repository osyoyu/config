## Comments

KEEP COMMENTS SHORT AND COMPACT. Comments should be one or two lines in general.

Comments shall state WHAT the code is. Only record WHY when the code's intention is very unclear; when we're doing hacks and tricks to acheive a specific goal. Course changes during implementation do not meet this criteria.
